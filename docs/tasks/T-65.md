## Fix

**Approach**: string literal trong `_class-refs.ts` (KHÔNG add dep + load plugin
như audit đề xuất). Lý do:

1. Pi-huly architecture = string literal cho TẤT CẢ class refs (Issue, Milestone,
   Project, ...). String sent to Huly server, server resolves class by string.
2. Standard Huly installation bundles `@hcengineering/document` plugin server-side
   → string `document:class:Document` resolves runtime.
3. Trusted huly-mcp loads plugin client-side CHỈ để lấy TYPE narrowing
   (`Document as HulyDocument`) cho operations code. Pi-huly dùng generic types,
   KHÔNG cần type narrowing → string literal equivalent.
4. Thêm dep + CJS require loader (như trusted `huly-plugins.ts`) = thêm dependency,
   thêm file, tăng bundle weight, KHÔNG thay đổi runtime behavior.

**Ponytail**: 1-line string change equivalent to audit's dep+loader proposal.
Same runtime, 0 new code.

## Deviation from audit

Audit đề xuất "thêm dep + load plugin + expose class refs". Deviation: dùng
string literal thay vì plugin loader. Đây là implementation approach choice
(KHÔNG architecture change) — outcome identical (correct class ref resolves
runtime). Ponytail principle: shortest diff achieving same behavior. Nếu
runtime verify sau cho thấy string KHÔNG resolve (self-host thiếu document
plugin), fallback = add dep + loader (deferred).
