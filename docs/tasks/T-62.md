## Vấn đề

Khi mở pi (`session_start`), `warmPool()` (T-55) → `getClient()` →
`createHulyClient()` → upstream `connect()` tải **toàn bộ model diff** từ server.
Upstream `@hcengineering/core@0.7.423` trong quá trình replay transaction qua
`ModelDb.addTxes()` (`core/src/memdb.ts:334-374`) gọi
`ctx.warn('no document found, failed to apply model transaction, skipping', …)`
mỗi khi một `TxUpdateDoc` / `TxRemoveDoc` / `TxMixin` đến mà **local model cache
không có doc** với `objectId` đó (cache-miss). Cùng cảnh báo phát từ
`core/src/client.ts:444` (`buildModel`) khi `hierarchy.tx(tx)` throw.

Kết quả: hàng chục–hàng trăm dòng warning **về cơ bản vô hại** (cache-miss khi
replay tx cũ cho doc đã expire/removed) **tràn ngập stderr**, che lấp mọi log có
ý nghĩa của pi + pi-huly (vd log tool call T-56). User báo "tràn break cả màn
hình pi".

Upstream `api-client` `connect()` **KHÔNG expose** `MeasureContext` / log-level
(`src/client/client.ts:148` gọi thẳng `connect(url, auth)`), không có seam chính
thống để tắt.

**Đây là 1 pattern trong một class rộng hơn** — upstream `@hcengineering` có
nhiều điểm `console.log`/`console.warn`/`console.error` không seam, đều break UI:
- **#67 (task này — T-62)** = `no document found` cache-miss warn (core/memdb +
  core/client buildModel).
- **T-64 (mới)** = `client websocket error: <id> <url-with-token>` + 7 dòng spam
  khác trong `client-resources/lib/connection.js` (session id, ping, version,
  protocol error, slow findAll) + **token leak security** (URL `_transactor/<token>`).
- **#68 / T-63** = khác root cause (silent data loss khi tool gọi updateDoc sai) —
  KHÔNG phải class này, nhưng cùng symptom "no document found" spam.

→ Cần **một filter framework tập trung** thay vì N filter rời rạc.

## Phương án (filter framework — danh sách pattern đăng ký, gate ở ranh giới pi-huly)

Xây module `src/client/console-filter.ts` (hoặc `_common`) export:
1. **`UpstreamConsoleFilter`** class — install/restore `console.warn`/`console.error`/
   `console.log` override. Match argument đầu tiên (string) qua danh sách pattern
   `RegExp[]`. Đếm số dòng đã filter (per-pattern + total).
2. **`runWithConsoleFilter(patterns, fn)`** — wrap một async block (vd quanh
   `connect()` / `warmPool`): install → run → restore (try/finally luôn restore).
3. **Pattern registry** — export `DEFAULT_UPSTREAM_NOISE_PATTERNS: RegExp[]`:
   - `/^no document found, failed to apply model transaction/i` (T-62 #67)
   - (T-64 đăng ký thêm sau khi T-62 ship — T-64 blocked-by T-62).
4. **Counter expose** — module-level counter, expose qua `health()` pool
   (`HealthStatus` thêm `upstreamNoiseFiltered?: { total: number; byPattern:
   Record<string, number> }`) → `/huly status` hiển thị `pool noise: N upstream
   log filtered (model-tx: X)`.
5. **Escape hatch** — config `quietUpstreamNoise?: boolean` (default `true`) +
   `upstreamNoisePatterns?: string[]` (user override danh sách pattern) trong
   `src/config/config.ts:26-34` `Config` type. Set `quietUpstreamNoise: false` →
   KHÔNG filter (debug thật).

Bounds:
- **Match argument đầu tiên** (string) qua pattern — KHÔNG filter nếu arg là
  object phức tạp không match (guard structured log: nếu arg có `message` field,
  match cả `message`).
- **Scope hẹp** — filter chỉ kích hoạt quanh `createHulyClient` / `warmPool` /
  sync model (wrap + restore sau khi connect xong). KHÔNG global-silent vĩnh viễn.
- **KHÔNG crash** — wrap nằm trong try/finally, luôn restore original console
  method dù block throw.
- **Pattern match FIRST-arg string** — một log khác (vd `console.warn('real
  error …')`) không match pattern → vẫn log ra (test guard).
