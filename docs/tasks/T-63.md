## Vấn đề

Warning class `no document found … TxUpdateDoc` (xem issue #67 / T-62 cho phần
noise quench) có **một root cause thứ hai** nằm trong pi-huly: khi một tool gọi
`client.updateDoc(_class, space, objectId, ops)` / `removeDoc(...)` với **`space`
HOẶC `objectId` sai**, server Huly KHÔNG throw mà **skip silently** transaction
(`ModelDb` tìm doc theo `_id + space` không match → skip) → update **KHÔNG
persist**, đồng thời broadcast `TxUpdateDoc` với objectId client không match →
cache-miss spam (xem #67).

Hậu quả nghiêm trọng hơn #67: đây là **silent data loss** — tool report success
nhưng data không lưu (giống bug #36 update_issue đã fix T-47, #40
update_user_profile đã fix T-50).

### Lịch sử bug cùng class

- **#40 / T-50**: `update_user_profile` truyền `space = objectId = currentUser.id`
  → cả 2 = `Person._id` → server skip → silent. Fix: lookup `Person.space` thật
  trước (`src/tools/domains/workspace.ts:130-173` — reference pattern).
- **T-61** (PR #66): `add_issue_relation` / `remove_issue_relation` từng đảo
  chiều blocks/is-blocked-by + thiếu chiều relates-to → push `$push` lên sai issue
  → silent no-op.

### Static audit hiện trạng (42 call site trong src/tools/domains/ — 30 updateDoc + 12 removeDoc)

Grep `\.updateDoc(\|\.removeDoc(` liệt kê **42 site**. **Phân tích đầy đủ**:

- **NHÓM A (OK — 42/42 site)**: `space` lấy từ **doc đã lookup** — `c.space`,
  `issue.space`, `t.space`, `m.space`, `existing.space`, `target.space`,
  `person.space`. Pattern an toàn: `findOne(class, {_id})` → guard `!doc` →
  `updateDoc(class, doc.space, doc._id, ops)`.
  - `comments.ts:107,140` · `components.ts:131,171,206` · `documents.ts:157,188`
  - `issues-core.ts:357,392,432,450,515,585` · `issues-relations.ts:106,118,143,149,228,239,259,264`
  - `issues-templates.ts:174,207,236,267` · `milestones.ts:151,191,226`
  - `projects.ts:133,170` (`existing.space`) · `spaces.ts:127`
  - `tag-categories.ts:78,109` · `tags.ts:85,118,207,270` · `todos.ts:208,234,262,295`
  - `workspace.ts:168` (`personSpace` — T-50 pattern)
- **NHÓM B (SUSPECT — 0 site)**: `space` từ `tctx.workspace` / param / default
  HOẶC `objectId` không rõ nguồn. **Sau T-50 + T-61, KHÔNG còn site nào match
  pattern sai**.

**Tuy nhiên, 41/42 site thiếu schema drift guard** (chỉ `workspace.ts:155-173`
có guard T-50). Các site còn lại dùng `doc.space as never` / `doc._id as never`
thẳng — nếu doc tồn tại NHƯNG `space`/`_id` field là `undefined` (data
corruption, partial import, schema drift), `undefined as never` được truyền
nguyên → server skip silent → **silent data loss + cache-miss spam (#67)**.

**Nhận định**: task này là **audit hardening** — KHÔNG còn bug pattern sai
hiện hữu, NHƯNG cần:
1. Thêm schema drift guard cho 41 site còn thiếu (centralize qua helper).
2. Đảm bảo regression không tái diễn (tool mới copy pattern sai).
3. Centralize logic qua `safeUpdateDoc` / `safeRemoveDoc`.
