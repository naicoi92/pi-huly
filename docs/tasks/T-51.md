## Vấn đề

Nhiều tool `create_*` dùng pattern `project?.space ?? tctx.workspace` — khi
`project` lookup trả `null` (project sai/đã xóa/identifier sai), code KHÔNG
báo lỗi mà fallback sang `tctx.workspace` rồi tiếp tục `createDoc`. Kết quả:
document được tạo vào workspace mặc định nhưng không thuộc project nào →
**document mồ côi**, và các TxUpdateDoc sau đó cho document này có thể bị skip
vì `space` không khớp nơi document thực sự nằm.

### Call sites cần sửa (verify code)

```
src/tools/domains/issues-templates.ts:84   (create_issue_from_template)
src/tools/domains/issues-templates.ts:121  (create_issue_from_template variant)
src/tools/domains/milestones.ts:93         (create_milestone)
src/tools/domains/components.ts:82         (create_component)
```

Pattern lỗi (đại diện milestones.ts:91-93):

```ts
const project = await tctx.client.findOne(PROJECT_CLASS, { identifier: tctx.project });
// project có thể null nếu identifier sai
const id = await tctx.client.createDoc(
  MILESTONE_CLASS,
  (project?.space ?? tctx.workspace) as never,   // ← fallback ẩn, tạo mồ côi
  { label: params.label, ... },
);
```

## Phương án

1. **Khi project lookup trả null → throw/return `NotFoundError` rõ ràng**,
   KHÔNG tiếp tục `createDoc`:

   ```ts
   const project = await tctx.client.findOne(PROJECT_CLASS, { identifier: tctx.project });
   if (!project) {
     return {
       content: `Project "${tctx.project}" not found. Run /huly init or check binding.`,
       isError: true,
       details: { project: tctx.project },
     };
   }
   // chỉ tạo doc khi project tồn tại
   const id = await tctx.client.createDoc(MILESTONE_CLASS, project.space as never, { ... });
   ```

2. Apply cho cả 4 call site. Pattern đã đúng sẵn ở `create_issue`
   (issues-core.ts:155-164) — reuse.
