## Vấn đề

Report #37 mô tả `huly_list_*` chỉ trả `"Found N item(s)."` — KHÔNG trả array
record. Đây **chính là bug #22 đã fix ở T-40** (PR #29, beta.2): builder seam
`appendDetailsForLLM()` auto-append `details` → `content` text khi `hasUI=false`.

Verify code hiện tại: `src/tools/builder.ts:291` vẫn có logic này.

```ts
// builder.ts:285-294 (đã fix T-40)
ctx.hasUI === false && result.isError !== true
  ? appendDetailsForLLM(contentText, result.details)
  : contentText,
```

→ Có 3 khả năng:

1. **User chưa update beta.2** (chạy beta.1 hoặc cũ hơn) → #37 là duplicate #22,
   không cần fix, chỉ yêu cầu user `pi update npm:pi-huly`.
2. **`hasUI` detect sai** — trong context của user, `ctx.hasUI` không phải `false`
   (vd agent runtime set sai, hoặc detect heuristic miss case). → `appendDetailsForLLM`
   không trigger.
3. **`appendDetailsForLLM` edge case** — details có shape mà helper không serialize
   đúng (vd nested array, empty details, sanitize strip quá mức).

## Phương án

1. **Verify version**: yêu cầu user confirm `pi-huly` version đang chạy (qua
   `/huly status` hoặc package.json). Nếu < 1.0.0-beta.2 → update rồi re-test.
2. **Nếu đã beta.2 mà vẫn lỗi** → investigate:
   - Log `ctx.hasUI` giá trị thực trong context user (agent runtime).
   - Test `appendDetailsForLLM` với exact details shape từ list_issues (có phải
     helper miss field nào không).
   - Có thể cần fallback: luôn append details summary (không phụ thuộc `hasUI`)
     nếu heuristic không đáng tin.
3. **Nếu là edge case** → fix `appendDetailsForLLM` hoặc `hasUI` detect, thêm
   regression test cover case đó.
