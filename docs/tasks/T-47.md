## Vấn đề (2 root cause)

`huly_update_issue({ identifier, status })` trả `"Updated issue LST-1: assignee, status"`
(báo success) nhưng `status` **KHÔNG persist** — get_issue ngay sau đó vẫn thấy
giá trị cũ. Đồng thời `assignee` bị auto-set thành current user dù caller KHÔNG
truyền `assignee`.

### Root cause 1 — D15 `needsAssignee` leak sang update

`src/tools/domains/issues-core.ts:230` khai báo `needsAssignee: true` trên
`update_issue`. Builder (D15 FR-18) auto-fill `params.assignee = currentUser.email`
khi absent → assignee bị set dù caller không yêu cầu. Đây là rule cho **create**
(`create_issue` line 132), KHÔNG nên apply cho `update`.

```ts
// issues-core.ts:230 — BUG
defineHulyTool({
  name: "update_issue",
  needsProject: true,
  needsAssignee: true,   // ← LEAK: chỉ create_issue mới cần default này
  ...
```

### Root cause 2 — status không map workflow enum / không verify

`issues-core.ts:266` chỉ `ops.status = params.status` — push raw string `"Done"`
thẳng vào server. Huly lưu status dạng full ref `tracker:status:Done` (get_issue
trả full ref). Có thể server reject transition nhưng tool nuốt error → silent
success. Hoặc status name format sai (short `Done` vs full `tracker:status:Done`).

Hypothesis từ report #36: Huly self-hosted reject status transition nhưng
WebSocket response không có error field, wrapper parse `OK` → return success.

## Phương án

1. **Remove `needsAssignee: true`** khỏi `update_issue` (line 230). Chỉ
   `create_issue` giữ rule D15. Builder không còn auto-fill assignee cho update.
2. **Validate status trước khi gửi server**: dùng `list_statuses` hoặc
   `findOne(ISSUE_STATUS_CLASS, ...)` resolve short name → full ref
   (`tracker:status:Done`) trước khi `ops.status = <full ref>`. Nếu status không
   hợp lệ → `isError: true` + suggest valid statuses.
3. **Read-back verify** (optional, defensive): sau `updateDoc`, `findOne` lại issue
   → assert field đã persist. Nếu mismatch → return warning/error thay vì
   silent success.
4. **Propagate server error**: nếu Huly reject update (WebSocket response có
   error) → throw/return error rõ ràng, KHÔNG parse OK giả.
