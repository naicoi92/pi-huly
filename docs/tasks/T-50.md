## Vấn đề

`huly_update_user_profile` gửi `TxUpdateDoc` bị Huly server (và mọi client đang
sync) skip vì `space` param sai. Verify code `src/tools/domains/workspace.ts:141-145`:

```ts
await tctx.client.updateDoc(
  PERSON_CLASS,
  idRef(tctx.currentUser.id),   // ← space: SAI — đây là Person _id, không phải Space ref
  idRef(tctx.currentUser.id),   // ← objectId: đúng
  operations,
);
```

Cả `space` (arg 2) và `objectId` (arg 3) đều = `currentUser.id`. Trong khi
`space` phải là Space ref của Person record, KHÔNG phải Person `_id`.

Hệ quả: warning
`no document found, failed to apply model transaction, skipping _class="core:class:TxUpdateDoc"`
spam cho mỗi update. Update không persist.

### Context root cause

Lỗi `no document found, failed to apply model transaction, skipping ... TxUpdateDoc`
là warning từ `@hcengineering/api-client` SDK khi apply TxUpdateDoc vào local
in-memory model nhưng document đích (match theo `_id` + `space`) không tồn tại.
Đây là bug upstream đã biết (hcengineering/platform#10772) NHƯNG pi-huly **kích
hoạt mạnh** vì nhiều call site gửi write với `space` sai (#41 + #42 cũng cùng pattern).

## Phương án

1. **Lookup Person record trước** để resolve `.space` đúng:

   ```ts
   const person = await tctx.client.findOne(PERSON_CLASS, { _id: idRef(tctx.currentUser.id) });
   if (!person) {
     return {
       content: `Person "${tctx.currentUser.id}" not found.`,
       isError: true,
       details: { userId: tctx.currentUser.id },
     };
   }
   await tctx.client.updateDoc(
     PERSON_CLASS,
     person.space as never,   // ← Space ref đúng của Person record
     person._id as never,
     operations,
   );
   ```

2. Defensive: nếu Person không tìm thấy → trả `NotFoundError` rõ ràng, KHÔNG âm
   thầm gửi TxUpdateDoc sai.
