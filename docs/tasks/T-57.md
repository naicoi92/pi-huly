## Vấn đề

Khi class ref sai runtime (vd `core:class:TsRelation`, `tracker:class:Document`),
tool trả về error generic `[InternalError] Internal: Error: domain not found: ...`.
Error này khó hiểu cho cả user lẫn LLM — không cho biết tool nào bị ảnh hưởng,
có phải lỗi cấu hình workspace không, hay bug pi-huly.

## Phương án (UnavailableError class)

Thêm error class mới `"Unavailable"` (distinct từ NotFound/Internal):

1. **`ErrorClass` union**: thêm `"Unavailable"` (8 classes total).
2. **`UnavailableError` class**: extend HulyError, có field `hulyClass` (class ref
   bị reject) cho context debug.
3. **`matchDomainNotFound(message)`**: regex `/domain\s+not\s+found:\s*(\S+)/i`
   extract class ref từ error message. Capture `\S+` (code-review MINOR #5) —
   defensive nếu Huly thêm class có ký tự lạ.
4. **`mapError` detect**: check cả PlatformError (UnknownError wrapping domain
   not found) LẪN plain Error (raw message). Trước fallback InternalError.
5. **`buildUnavailableMessage(cls)`**: list possible causes (package chưa enable /
   sai class ref / rename deprecated) giúp user/LLM debug.
6. **Builder render**: duck-type `hulyErr.class === "Unavailable"` (KHÔNG
   `instanceof` — compatible test mock) → render `[UnavailableError]` + recovery
   hint + `details.hulyClass`.

## Regression guards

- Network errors (ECONNREFUSED, fetch failed) check TRƯỚC domain-not-found →
  vẫn map ConnectionError.
- PlatformError UnknownError KHÔNG chứa "domain not found" → vẫn InternalError.
- Generic plain Error → vẫn InternalError (no false Unavailable upgrade).
- ExternalError unwrap → UnavailableError nếu cause match domain not found.
