## Vấn đề

Nhiều tool nhận user input là entity reference (`targetIssue`, `component`,
`milestone`, `parentIssue`, `document`, `tag`) rồi cast trực tiếp thành `Ref<T>`
qua `idRef(params.xxx)` và ghi vào Issue — **không validate** entity đó có tồn tại.
Hệ quả:

1. Issue update thành công về phía tool (lừa LLM).
2. Khi *client khác* (subagent, UI) sync và apply TxUpdateDoc cho target document
   không tồn tại → warning `no document found, failed to apply model transaction,
   skipping _class="core:class:TxUpdateDoc"` spam cho mỗi ref rác.
3. Dữ liệu Issue bị ref rác (vd `component: <bogus-id>`), không nhất quán giữa các client.

## Pattern chuẩn (đã đúng ở `add_issue_label` T-45 PR #34 + `remove_issue_relation`)

```ts
const target = await tctx.client.findOne(TARGET_CLASS, { _id: idRef(params.targetId) });
if (!target) {
  return {
    content: `Target "${params.targetId}" not found.`,
    isError: true,
    details: { target: params.targetId },
  };
}
// chỉ mới gọi updateDoc/addCollection sau khi target verified
```

## Phương án

1. Áp dụng pattern chuẩn cho 7 tool trên — `findOne` target entity trước khi
   `updateDoc`/`addCollection`/`removeDoc`.
2. **`add_issue_relation` đặc biệt**: vì `targetIssue` nhận identifier (`PD-123`)
   chứ không phải raw `_id`, phải resolve identifier → `_id` trước (dùng
   `resolveIdentifier` rồi `findOne(ISSUE_CLASS, { identifier })`).
3. **`unlink_document_to_issue`**: $pull idempotent → optional skip nếu không
   tồn tại (không cần hard error). Nhưng vẫn nên validate để bắt typo sớm.
4. **Code reuse**: extract helper `assertEntityExists(client, _class, id)` ở
   `_common.ts` nếu phù hợp, tránh lặp 7 lần.
