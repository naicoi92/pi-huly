## Vấn đề (2 mặt cùng root cause)

- **#22 — `list_*` giấu data array**: `src/tools/builder.ts:284-288` chỉ đưa
  `result.content` (text) vào `AgentToolResult.content` tới LLM, bỏ qua
  `result.details` (nơi 25 list tools đặt data array). Path agent non-TUI
  không có TUI render → data mất hoàn toàn.
- **#26 — `create_*`/`add_*` giấu `_id`/`identifier`**: cùng cơ chế — 21 tool
  create/add (create_issue, add_comment, create_milestone, create_component,
  create_label, create_tag, create_todo, create_issue_template, add_attachment,
  add_issue_attachment, ...) đặt `_id`/`identifier` của entity vừa tạo vào
  `details`, nhưng `content` chỉ chứa message như "Created issue ...". LLM
  không biết id → không gọi update/delete/get/link được → entity bị orphan.
  Chỉ 2 tool đã đúng convention: `create_document` (đã có `id: ${id}` trong
  content), `create_project` (đã có identifier trong content).

Cùng package có 2 convention mâu thuẫn: `get_issue` đặt full data trong
`content`, list/create tools đặt trong `details`.

## Phương án

Prefactor tại 1 chỗ duy nhất (builder.ts) — khi detect non-TUI mode (no
render context), auto-append `details` sang `content` text để LLM thấy array
(cho list) + id/identifier (cho create/add). Có thể kết hợp cap array
(top 30 + "... và N khác") tránh bloat context. Giữ `details` nguyên vẹn
cho TUI path (render/*.ts vẫn hoạt động).

### Bonus schema fix (ngoài builder)

`create_issue` hiện `details: { id, title }` — thiếu `identifier` (vd `LST-32`)
mà LLM cần cho 90% tool khác (`get_issue`, `update_issue`, `add_comment`...).
`createDoc` trả `_id` nhưng không trả identifier ngay → cần thêm bước lookup
sau khi tạo (query `findOne(ISSUE_CLASS, { _id })` để lấy identifier), hoặc
surface `_id` kèm hướng dẫn LLM. Làm trong cùng task này vì cùng chủ đề
"create phải surface đủ id cho LLM manage lifecycle".
