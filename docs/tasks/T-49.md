## Vấn đề

`huly_fulltext_search` fail với `domain not found: tracker:class:Document`.
Tool description nói "Substring search across Huly workspace" nhưng mọi query
đều lỗi. T-42 (PR #33) đã expand search 3-domain (Issue + Document + ChatMessage),
nhưng Document domain dùng class sai runtime.

```ts
// search.ts:85 (sau T-42 + T-43)
searchDomain(tctx.client, DOCUMENT_CLASS, "title", query, limit, "document"),
// DOCUMENT_CLASS = "tracker:class:Document" (T-43 rename, nhưng runtime vẫn lỗi)
```

`searchDomain` catch server reject `$like` → honest error (T-42 đã fix). Nhưng
vì class sai → reject ngay → toàn bộ search fail (Promise.all reject nếu 1
domain throw).

Hypothesis từ report #38 + audit §7: `tracker:class:Document` có thể vẫn sai.
T-43 audit dựa trên npm tarball source map, KHÔNG verify runtime server
(workvps unavailable). DocumentSnapshot cũng UNVERIFIED (audit §7).

## Phương án

1. **Runtime verify** Document class thật (pair với T-51 nếu cần server, hoặc
   inspect `core:class:Class` registry). Các khả năng:
   - Document thuộc package khác (vd `chunter:class:Document`?).
   - Document class đã deprecated, thay bằng class khác.
2. **Cách dùng đúng**: nếu tìm được class đúng → update `_class-refs.ts` +
   `docs/design/11-runtime-audit.md` truth table.
3. **Defensive fallback** (nếu không verify được ngay): catch `domain not found`
   riêng cho Document domain → log warning + tiếp tục search Issue + ChatMessage
   (KHÔNG để 1 domain fail kéo cả Promise.all). User vẫn search được issue/message
   trong khi Document domain pending fix.
4. **Honest tool description**: nếu Document search không work → note rõ trong
   tool description "Document search currently unavailable" thay vì overclaim.
