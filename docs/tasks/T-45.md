## Vấn đề

`src/tools/domains/issues-core.ts:331-340` — `add_issue_label` push raw
string `idRef(params.label)` vào `issue.labels` mà không `findOne(LABEL_CLASS, ...)`
verify label tồn tại. Label không tồn tại vẫn "Added label ..." thành công →
issue mang ref rác, UI Huly có thể crash/render sai.

```ts
// hiện tại — KHÔNG validate
const labels = ((issue as { labels?: unknown[] }).labels ?? []) as unknown[];
if (labels.some((l) => l === params.label)) { ... no-op ... }
await tctx.client.updateDoc(ISSUE_CLASS, issue.space as never, issue._id as never, {
  $push: { labels: idRef(params.label) },   // ← push raw string, KHÔNG verify
});
```

Không có bước `findOne(LABEL_CLASS, { title: params.label })` để confirm label
tồn tại. Cũng không normalize (Huly label ref có thể cần format `<id>` hoặc
object `{ _id, label }` — raw string có thể không đúng shape).

## Phương án (sau T-44 xác định ref shape thật)

1. Thêm bước validate trước khi push:

   ```ts
   const label = await tctx.client.findOne(LABEL_CLASS, { title: params.label })
                 ?? await tctx.client.findOne(LABEL_CLASS, { _id: params.label });
   if (!label) {
     return { content: `Label "${params.label}" not found. Create via create_label first.`,
              isError: true, details: { label: params.label } };
   }
   // push label._id theo đúng shape (string hoặc object — phụ thuộc T-44)
   ```

2. Apply đối xứng cho `remove_issue_label` (issues-core.ts:348+) và `attach_tag`
   (tags.ts — cũng broken per #25, sau khi TAG_CLASS fix).
3. Bonus: chấp nhận cả label title (human) LẪN id — clarify trong tool description.
